# Ticket types and templates

## Deliverable

```markdown
## Outcome / why
## Scope
## Acceptance criteria
## Non-goals
## Context and decisions
## Dependencies / risks / unknowns
## Test approach
## Release, recovery, and observation
```

## Bug

```markdown
## Impact
## Observed behaviour
## Expected behaviour
## Reproduction and evidence
## Environment / affected scope
## Acceptance criteria
## Regression test
## Release, recovery, and observation
```
Keep severity/impact evidence separate from backlog priority.

## Spike

```markdown
## Decision or question
## Why now
## Timebox / boundary
## Investigation approach
## Evidence or outputs
## Exit criteria
## Follow-up decisions
```
A spike buys a decision or reduced uncertainty, not an implementation promise.

## Debt

```markdown
## Current pain / risk and evidence
## Intended improvement
## Scope / non-goals
## Acceptance criteria
## Verification
## Migration, release, and recovery
## Success observation
```

## Child task

```markdown
## Action
## Completion evidence
## Parent ticket
## Dependency / blocker
```
Keep context and acceptance on the parent unless the child has an independently reviewable result.
