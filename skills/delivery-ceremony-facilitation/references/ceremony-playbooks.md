# Ceremony playbooks

## Kickoff — as required
Outcome: shared intent, roles/hats, boundaries, risks, and downstream expectations before material effort.
Invite: owner, delivery/quality/design hats doing the work, and relevant stakeholders.
Flow: context and outcome → scope/non-goals → design/test/release/monitoring implications → questions/decisions → owners and next gate.

## Planning — each cycle/sprint where used
Outcome: one cycle goal and a credible plan drawn from ordered, ready-enough work.
Invite: whole cross-functional delivery team.
Flow: capacity/interrupts → goal → select from backlog top → dependency/risk check → maintenance allowance per local policy → confirm plan and ownership.
Do not treat a cycle as a release.

## Daily stand-up / flow review
Outcome: adapt today's plan, unblock flow, and coordinate around the goal.
Work from the board: aging/blocked first → what moved → next pull/coordination → park deep discussion.
Not a status report to a manager.

## Refinement / triage — commonly weekly
Outcome: explicit dispositions, sizing/feasibility input, near-term order, and a small set of refinement actions.
Invite: owner plus delivery, quality, and design hats; sponsor/stakeholder as needed.
Do not rewrite all prose in the full-group session.

## Showcase and review — each cycle/sprint where used
Outcome: inspect the delivered result and context, account for commitments, gather feedback, and adapt what comes next.
Flow: restate goal → live evidence/demo → finished/not-finished and why → operational/outcome signals → stakeholder feedback → backlog decisions.
Show the thing, not the ticket. The review is not a release gate.

## Retrospective — each cycle/sprint where used
Outcome: improve quality and effectiveness of the team's working system.
Flow: establish facts → generate observations → find patterns/causes → choose one or two experiments → owner, success signal, review date.
Separate product feedback from process improvement.

## Postmortem — when explicit local triggers or stakeholder judgment require it
Outcome: factual, blameless understanding and systemic prevention after a significant incident or project event.
For an incident: impact → timeline → detection/response → contributing conditions → what helped/hurt → corrective/preventive actions → review/publication.
For a project event: intended versus observed outcome → timeline/decisions → contributing conditions → what helped/hurt → systemic follow-up → review/publication.
Define trigger criteria locally; do not invent universal thresholds.
